# RA Source-System Simulation

The `cdm_tmforum` golden data already exists. This skill covers the **upstream source
systems** that a real operator would land *before* MDM — generated by
`data-sim/simulate_source_systems.py` (+ `data-sim/config.yaml`) in this repo, run as the
`simulate_source_systems` notebook in the workspace. Full spec:
[`demo-artifacts/04-source-data-spec.md`](../../../demo-artifacts/04-source-data-spec.md).

Route Databricks work through `databricks-core`; never auto-select a profile (pass
`--profile <name>`, get it from `databricks auth profiles` or ask the user). Use the
`databricks-synthetic-data-gen` skill for generation patterns and
`databricks-unstructured-pdf-generation` for the branded documents.

## Non-negotiable rules
- **Do not touch `tmf_*`** — read-only. Write only the `*_source` schemas (and `mdm_source`).
- **MDM-consistency:** anchor every source record to a real golden customer by reading
  `cdm_tmforum.tmf_customer.customer` and carrying its keys (`external_customer_code`,
  `customer_id`). Emit `mdm_source.customer_crosswalk` (source→golden + match confidence).
- **Real provider schema/field names**, not invented ones: Salesforce `Account`, `Contract`,
  `SBQQ__Quote__c`/`SBQQ__QuoteLine__c`; Oracle `RA_CUSTOMER_TRX_ALL`,
  `AR_PAYMENT_SCHEDULES_ALL`, `GL_JE_LINES`, ASC-606 rev-rec; Refinitiv `GL_DAILY_RATES`;
  Ironclad contract records.
- **Natural distributions** (the golden data is statistically flat): power-law B2B account
  sizing, log-normal contract value, DSO by credit class, Q4 seasonality. Derive ERP AR
  invoices from `tmf_customer.bill` so finance and billing reconcile to the same invoices.
- **Comment everything:** `COMMENT ON TABLE` + `ALTER COLUMN … COMMENT`.
- **Branding:** unstructured docs (MSAs, invoices, dunning letters) are **Lakelink Fiber**
  (Databricks logo as the mark). Keep the letterhead/palette consistent.

## Anomaly injection (for the ML / `ai_forecast` scenes)
Base data has no sharp signal, so seed a small, clearly-flagged set of anomalies
(bandwidth step-ups without billing increase, retroactive discounts, mediation-failure
bursts) via a `LEAKAGE_RATE` / anomaly knob. Set it to 0 for pristine data. This is
separate from the ~$540M native seeded leakage already in `tmf_enterprise.revenue_assurance_violation`.

## Reset / regenerate
1. Edit `data-sim/simulate_source_systems.py` locally, then run it as the
   `simulate_source_systems` notebook in the workspace (`# Databricks notebook source` format).
2. Review `data-sim/config.yaml` / the CONFIG cell (`CATALOG=cdm_tmforum`, scale, seed, anomaly
   rate) — then run.
3. Regeneration is idempotent (`CREATE OR REPLACE`); it drops/recreates only `*_source`
   schemas and re-emits the crosswalk. Never regenerate or drop `tmf_*`.
